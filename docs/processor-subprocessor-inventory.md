## Current Launch Inventory

### 1. Cloudflare

- Role:
  - application hosting and delivery
  - Cloudflare Workers runtime
  - Cloudflare D1 database infrastructure
  - Turnstile bot protection when enabled
- Product surfaces:
  - all app requests served through the deployed app
  - signup bot checks when Turnstile is configured
  - database-backed account, profile, group, session, moderation, and audit data
- Data involved:
  - account and community data stored in D1
  - request metadata and operational/security logs handled through app infrastructure
  - Turnstile technical signals and challenge data when signup protection is active
- Why it is in scope:
  - it is a core infrastructure provider and handles personal data needed to run the service

### 2. Resend

- Role:
  - transactional email delivery
- Product surfaces:
  - email verification
  - password reset
  - email change confirmation
- Data involved:
  - recipient email address
  - subject line
  - email body content needed to deliver account emails
- Why it is in scope:
  - it processes user contact data and message content on behalf of Melon Meet

### 3. OpenFreeMap

- Role:
  - default external map style and tile delivery for the frontend unless the operator overrides the map-style environment variables
- Product surfaces:
  - the map UI when using the default style configuration
- Data involved:
  - typical web request data generated by loading remote map styles and tiles, such as IP address, browser metadata, and requested tile/style URLs
- Why it is in scope:
  - the current default frontend configuration loads map resources from `tiles.openfreemap.org`

## Conditional or Deployment-Dependent Providers

These are not fixed named processors in the current repo state, but they become part of the operational data-flow picture when configured.

### Alert webhook destination

- Role:
  - receives operational error alerts when `ALERT_WEBHOOK_URL` is configured
- Data involved:
  - app/environment name
  - request path and method
  - request, user, or session identifiers when present in the alert payload
  - error message and operational context
- Current status:
  - provider is not fixed in the repo
  - document the concrete destination before broad launch if alert webhook delivery is enabled in production

### Custom map style provider

- Role:
  - replaces OpenFreeMap if `VITE_MAP_STYLE_URL` or `VITE_MAP_STYLE_URL_DARK` points to another external provider
- Current status:
  - not fixed in the repo today
  - if a custom external style is used, update this inventory and the privacy copy

## Not Currently Configured as Launch Providers

- No analytics provider is implemented in the current codebase.
- No marketing email provider is implemented in the current codebase.
- No separate SaaS error-monitoring vendor such as Sentry is implemented in the current codebase.

## Public Privacy Copy Implications

The privacy materials should currently disclose at least:

- Cloudflare for hosting, infrastructure, D1 database services, and Turnstile bot protection
- Resend for transactional email delivery
- OpenFreeMap as the default external map style/tile provider unless replaced by a self-hosted or alternative style setup

The privacy materials should also avoid claiming:

- EU-only hosting or processing
- that there are no processors or no international transfers
- that map resources are always served only from Melon Meet infrastructure

## Review Rules

- Re-review this inventory before broad public announcement.
- Update it whenever:
  - analytics is added
  - a new monitoring or alerting vendor is enabled
  - a new map/tile/style provider is configured
  - file storage, media hosting, or customer-support tooling is added
